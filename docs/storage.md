# Bevy 网页版存档

本次重构使用新格式和独立数据库。旧网页版本与 Windows 原版存档不兼容；客户端不读取、迁移或导出旧网页数据库。

## 数据库与文件

IndexedDB 数据库为 `virtual-life-bevy`，数据库版本为 1。`saves` 表以 `slot` 为键保存 `current` 和 `previous`；`settings` 表单独保存音量等选项。素材的 CacheStorage 与存档数据库相互独立。

浏览器记录及导出文件使用以下外层字段：

```text
format: virtual-life-bevy-save
version: 1
savedAt: 保存时间
contentId: 当前规则内容标识
payload: Rust 核心存档及 Bevy 场景状态的 JSON 字符串
checksum: payload UTF-8 字节的 SHA-256
```

数据库记录另有槽位字段。Rust 核心的 payload 也带格式、版本、内容 hash、状态 checksum 和完整业务状态；外层文件校验通过后，核心仍会检查状态结构、地图坐标、活动记录、物品数量、随机数等约束，再执行恢复。

Bevy 在 payload 的 `presentation` 字段保存镜头、原生界面选择与计时、动画帧和未完成的行走表现，全部字节受外层 SHA-256 校验保护。恢复时先校验表现结构，再移除此字段并交给核心严格验证领域存档；成功后重建显示和音频实体。按住的物理输入、IME 和测试输入不会恢复。

内容标识根据解析后的规则目录规范化生成，统一对象键顺序、整数浮点表示与负零。实际规则内容变化会使旧内容标识失效，不通过忽略版本或校验值强行接受存档。格式字符串与旧客户端不同，即使版本号都为 1 也不互通。

## 保存与恢复

`F6` 打开画布内存档管理，可保存当前进度、读取当前记录、恢复上一份备份以及导入和导出新格式文件。原版界面中的系统操作也可进入相应保存或读取流程。

同一连接按保存调用顺序执行写入。SHA-256 计算在读写事务外完成，再在事务内核对原记录是否仍为读取时的版本；存在跨页面冲突时有限重试。有效的旧 `current` 被原子移动到 `previous`，然后写入新 `current`。损坏的当前记录不会覆盖上一份有效备份，事务失败会回滚两个槽位。

读档和文件选择结果按请求编号接收；切换页面或发起更新的读档后，迟到的旧结果被丢弃。自动保存的成功消息不覆盖原版建角画面；存档管理中仍显示保存结果和错误。

导入文件限制为 8 MiB，并检查格式、时间字段、内容标识和 SHA-256；随后由 Rust 核心检查完整状态。导出只从新数据库取出经过校验的记录。不要手动修改 payload、hash 或 checksum 作为“修复”手段。

## 故障与更新

存储配额不足、事务失败或浏览器不允许 IndexedDB 时会报告错误；仍已提交的记录应保留。损坏记录可尝试上一份备份或外部导出文件。清除网站数据、浏览器清理策略或用户删除配置文件会删除本地记录，因此重要进度需要另存导出文件。

素材缓存写入失败不删除存档，也不阻止联网读取。Service Worker 更新应用壳时不清空新存档数据库。显示设备丢失会暂停运行并尝试保存，之后刷新页面重建 WebGPU 设备；恢复仍以最近一次成功提交的记录为准。
