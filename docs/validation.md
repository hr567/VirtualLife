# 验证与验收

重构的目标是原版玩法和画面一致，同时继续以网页为唯一目标客户端。验收应分别记录资源、算法、表现、浏览器和原程序对照证据，不能用某一层通过替代其他层。

2026-10-29 的具体执行环境、检查结果和未通过门槛见 [本次验证记录](verification-2026-10-29.md)。

## 自动检查

| 检查层 | 命令或入口 | 证明范围 |
|---|---|---|
| 原资源与提取格式 | `pnpm verify:assets`、`pnpm test:formats` | 原始字节、路径、SHA-256、长度、结构和已固定的异常边界 |
| Rust 工作区 | `cargo test --locked --workspace` | 原机器码样本、存档约束、核心流程、表现资源和物理输入规则 |
| 浏览器适配 | `pnpm test:platform` | 存档事务、缓存校验、下载合并、配额和预取调度 |
| 完整解码 | `validate_assets` example | 原位图、PCX、FLIC 和固定异常资源的解码范围 |
| 实际网页客户端 | `pnpm test:fixtures`、`pnpm build:test`、`pnpm test:web` | 当前测试用例执行的真实 Bevy WASM、输入、像素、存储和页面场景 |
| 生产产物 | `pnpm build`、`pnpm verify:dist` | 生产 WASM、实际 LFS 文件、静态子路径、应用壳和体积预算 |

Rust 测试保留 `tests/fixtures/original-*.json` 中的原指令差分样本。场景测试从原素材自身推导几何和预期像素：例如从侧栏透明切口测量四个 HUD 按钮，核对正常、悬停、按下和释放帧，避免实现和测试共享同一套错误坐标。

浏览器测试用例位于 `tests/bevy-web/`。生产页面不提供测试输入接口；确定性时间和输入由单独测试构建启用，平台检查还限制其运行来源。测试场景使用本次新存档格式，不重新引入旧网页存档兼容。

## 浏览器环境和证据

默认 Playwright 使用实际 Chromium WebGPU，Linux CI 通过软件适配器执行。`PLAYWRIGHT_GPU=hardware` 使用当前浏览器实际提供的设备，`PLAYWRIGHT_CHANNEL` 可指定已有 Chromium 系浏览器通道。WebGPU 对象存在但没有可用适配器时，不能计为画面测试通过。

截图和失败证据默认写到系统临时目录，可通过 `PLAYWRIGHT_OUTPUT_DIR` 指定。测试完成状态、用例数量、跳过项和退出码以本次运行报告为准。源码中已存在测试、或曾在旧 TypeScript 客户端通过，不代表它们已在当前 Bevy 客户端运行通过。

功能验收需覆盖建角与中文输入、完整回合、所有小游戏和奖励、关系与问答、大赛、普通和最终战斗、物品和参数页、房产转场、结局与轮回。平台验收还需覆盖长帧与隐藏恢复、键盘和多触控释放、9 个存档位置、投骰前自动保存与旧双槽原子迁移、坏文件拒绝、缓存损坏、离线未命中、更新接管、横竖屏及设备丢失。应在报告中区分已执行场景和待执行场景。

## 原版保真边界

主菜单或 HUD 与原素材逐像素一致，只能证明对应场景和状态。完整原程序 GUI 对照还需要在固定输入、时钟、原程序版本和显示基线下比较完整场景、动画、音频与结果。经用户允许，原 GDI 文字采用文泉驿点阵宋体近似字形；字体测试验证固定资源、布局和合成行为，不再要求该部分与原 GDI 字形逐像素相同。原版自带位图文字和图像素材仍按原字节验证。现代 Windows 取得的 GDI 调色映射也不能单独证明 Windows 9x 全屏画面一致。

原程序已确认的死循环、未初始化内存、越界指针和未引用的坏资源继续按 [保真边界](fidelity.md) 处理，不通过自拟规则消除这些差异。Android Chrome、iPhone/iPad Safari 真机与原 Windows 游戏完整 GUI/像素对照，只有取得对应设备和可复核记录后才能标为通过。

完整人生探针通过公开命令运行，不编辑属性、跳过阻塞或伪造胜利。探针完成一条固定策略路线不表示所有人生阶段和分支已覆盖，也不表示 Bevy 的全部可见 UI 已验收。
